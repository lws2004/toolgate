## 4. 需要修正/精确化的三处

### 4.1 A1 的影响面应收敛到「服务端聚合」

Hy4 说「§21.7.1 的目标链路、§18.4 的可重放都依赖一个跨请求的 turn 边界」。严格说：

| 设计 | 是否依赖服务端 turn | 说明 |
|---|---|---|
| §13.4 方案 B（d1 请求级批处理） | **是** | 服务端要把多个独立 MCP 请求的判定点聚合成一次 d1 调用，必须有 turn_id |
| §22 L1 预判（跨调用缓存） | **是（弱）** | 预判可以按 request 做，跨请求聚合才需要 turn |
| §21.7.1 Task Input → 本地 agent → tools/call | **否** | turn 状态在本地 agent（调用方）里，服务端不需要 |
| §18.4 可重放 / checkpoint | **否** | 调用方记录「已完成哪些调用」，服务端只需每次调用确定 |

建议 A1 的结论不变，但把 `_meta.toolgate/turn` 定义为**可选字段**：传了才做跨请求聚合，不传退化为方案 A。这样不会把「所有请求都必须带 turn」变成新的协议负担。

### 4.2 B3 的 imageHash 应升为 P0（协议合规）

`research-notes-external.md:63` 明确写「imageHash 不属于 MCP 规范，应放在 `_meta` 或 `structuredContent`」。代码 `Content::to_mcp` 却把 `imageHash` 放进 image block：

```json
{ "type": "image", "mimeType": "...", "data": "...", "imageHash": "..." }
```

MCP 的 ImageContent 只有 `{type, data, mimeType, annotations?, _meta?}`。严格校验的客户端会拒绝这个结果。这不是「调研结论未回流」的技术债，是**协议兼容性问题**，应放在 P0 或 P0.5。

### 4.3 C2 的 ADR 引用位置

Hy4 写「ADR 与正文『三条约束』是两套」，引用的是 ADR 0001:32（那一行是「41 个测试」）。真正的两套是：

- ADR 0002 的三条：缓存前缀稳定 / 治理规则集中 / 语义边界清晰；
- 架构 §4.0 的三条：正交 / 上下文预算 / 智能层门槛。

两套都成立，但必须统一为一套（建议正文 §4.0 采用 ADR 0002 的三条，因为它们是「为什么是 6 个」的直接论证；「智能层门槛」可以并入「语义边界清晰」）。

## 5. 合并后的最终清单

### P0（定稿前必须处理，7 条）

1. **A1 turn 载体**：`_meta.toolgate/turn`（turn_id、seq、budget，可选），服务端聚合状态只在 turn 内、可丢弃；§13.2 补「_meta 解析 + 新旧协议兼容层」。
2. **A2 + P0-2 本地副本与脱敏顺序**：§8 增「本地副本」小节（权限、TTL、none 档是否禁止落盘、路径信息面）；§9.3 定义「截断 → 脱敏 → 落盘 → 摘要 → 再脱敏」顺序；spill/snapshot 权限 0600/0700。
3. **A3 单一决策表**：纯函数 `(intent, path_rule, isolation_default, max_exposure, content_rules, upstream_capability, slot_available, latency_budget) → (output_shape, fallback, meta)`，配属性测试；各章引用它。
4. **P0-1 命令输出隔离**：bash/search 增加内容级规则，路径 glob 覆盖不了 `cat .env`。
5. **P0-3 meta 双通道**：凡影响模型判断的告知必须进 content 文本，structuredContent 只放程序字段。
6. **P0-5 可重放副作用**：§18.4 分「只读可重放 / 写工具需调用方 checkpoint」，写工具引入 operationId。
7. **B1 执行模型**：先定性串行是 v1 实现约束还是 v2 架构约束；若是后者，补并发模型与排队预算；若是前者，§3.1 加排队预算，§15.4 并发 edit 升级为并发模型决策。

### P0.5（协议合规，1 条）

8. **B3 imageHash**：移到 `_meta` 或 `structuredContent`；同时补 `outputSchema` 声明与 ToolError 重构进 §13.3。

### P1（阶段 1 前，6 条）

1. **B2 信任域**：一个 server 实例 = 一个信任域；多信任域用多实例，共享一个 SLM HTTP 服务（注意多实例内存账）。
2. **P1-2 兼容性默认值**：v2 首版默认 raw，auto 显式开启。
3. **P1-4 快照字节级**：`snapshot(path, &[u8])`；write 解码错误拒绝。
4. **P1-5 单二进制矛盾**：拆「纯 L0 版 / 带 SLM 版」；补多模型内存账；评估 candle。
5. **P1-1 错误码**：稳定 errorCode 枚举 + ToolError 三处不一致修正。
6. **C3 证据等级**：每个成本数字标「实测/估算/假设 + 日期 + 硬件」；§15.4 落成基准脚本。

### P2（批量修，3 组）

1. **C1 check-doc.sh**：自动提取最大章节号 + 校验 §N 引用存在性；当前 207 处引用无悬空，但脚本没有防回归能力。
2. **C2 文档元数据**：测试数统一（41/47/57 → 以 CI 为准）、ADR 0002 三条约束与 §4.0 统一、核对表基线由脚本生成。
3. **我报告 §4 的 15 条文档矛盾**：逐条批量修。
