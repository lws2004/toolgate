## 八、四类改变的具体说明

### 1. 哈希锚点：从默认特性收窄为可选模式

原设计把哈希锚点当作 read/edit 的默认行为。现在改为 read 的 anchor 参数
可选，默认关闭。

**理由**：每行多约 7 字节。小文件、一次性编辑时，锚点的开销超过它省下的
oldText 回传量。只有「大文件 + 反复改少量行」才划算。

**价值未丢**：机制完整实现（4 位哈希、归一化容错、失配拒绝写入），
只是加了启用判据。

### 2. 断点续传与 Checkpoint：从工具层移到调用方

原设计把 checkpoint 放在 Rust 执行引擎里。现在归调用方，契约在 §18.4 定义。

**理由**：「任务完成了没有」需要知道目标，而工具层没有目标；「跑到第几步」
需要看 agent 循环，工具层看不到。这两件事工具层做不了。

**价值未丢**：task 工具保证「进程可寻址、输出可增量读取」，
调用方保证「记录已完成的步骤」。两者组合才构成完整续传。

### 3. 超长文本折叠：从统一落盘改为按需

原设计要求 read 也把超长内容落盘。现在只有单行超长时才落盘。

**理由**：文件本来就在磁盘上，指针就是原路径，再存一份是浪费；
且给 offset 比给临时文件路径更直接。

**价值未丢**：可回溯性由原文件本身保证。

### 4. rpi-plugin-sdk：不做

**理由**：插件形态要求工具跑在宿主进程内，共享生命周期与内存，
与「本地常驻、跨 agent 复用」的目标冲突。MCP 已经解决了跨 agent 复用。

**价值未丢**：通信网关的另外两种形态（MCP Server、CLI）都实现了。

| 项 | 强化方式 |
|---|---|

| 云端成本平衡 | 三个场景的实测账（省 114 倍 / 信息有损 / 不该走） |

## 十、一句话总结

**原架构的四个核心价值——工具鲁棒性、缓存与成本、续航与自愈、中立与可演进
——全部保留。改变的是「谁来做」，不是「做不做」。**

唯一的实质收窄是哈希锚点从默认改为可选，而那是因为原设计没有算过它的成本。

复核补记（2026-11-04）：四条价值在正文里各有一处「表里写着、正文没有」的
断点——快照回滚引用了一个不存在的旧章节号、类型嗅探只有名字、图片压缩级序只在
代码里。本轮已把它们补成正文（§20、§10.4、§10.2d）。**价值本身没变，变的是
「文档能不能支撑这个价值」。**

重算补记（2026-11-04）：成本账原来只算了「直连云端」一种形态，那个 110 倍
在那一个形态下成立。重算后三种形态各有回本判据——F1 算 token，F2 算事故成本，
F3 算合规与可用性。**价值没有消失，是度量单位换了。**
