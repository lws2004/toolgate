## 8. 数据隔离

数据隔离是**可选的加固层**，不是本架构的前提（重新定位后，价值主要由「进上下文前的
成形」承担，§1.6）。它依赖增强层介入：内容在进入 agent 上下文之前，由增强层
（本地 SLM 或经 `govern` 反向委派的 agent 模型）决定「变成什么形状再走」。
隔离档位表达的是「**送给会看这段内容的那次增强调用多少可见信息**」——本地 SLM
时等同不出机；委派模型时等同不出本机、但会交给该会话模型。

### 8.1 四档隔离强度

从强到弱：

| 档位 | 交给增强调用什么 | 由谁实现 | 丢失什么 |
|---|---|---|---|
| none | 什么都不上传，返回 `IsolationRefused` 错误（§1.4.5） | 策略层 | 全部 |
| understand | 只上传判定结果（类型、有无错误、数量） | classify / decide 槽位 | 具体内容 |
| summary | 上传摘要 + 原始指针 | summarize 槽位 | 原文细节 |
| raw | 原文 | 无 | 无 |

**understand 是最有特色的一档**：它之所以成立，是因为 jev 类模型
**不生成 token**——输出是受限的答案集合，所以不存在「摘要里意外带出
敏感信息」的可能。它只回答「这段内容属于哪一类」。

**注意（重新定位后）**：understand 档成立的前提是判定模型**不生成 token**
（jev / systemone 类受限输出）。反向委派给**生成式会话模型**时，模型必须先读到
原文才能判定，此时 understand 档退化为 summary / raw——因此 understand 仅对本地
jev / systemone 类判定槽位成立，委派模型下的最低可用档是 summary。

### 8.2 各工具能提供的隔离

| 工具 | 最强可做到 | 丢失什么 |
|---|---|---|
| bash | understand（只说「有 3 个测试失败，类型是超时」；输出内容级规则见 §8.11） | 具体断言内容 |
| search | understand（只说「命中集中在 auth 模块」） | 具体行 |
| read（文本） | summary | 原文细节 |
| read（图片） | understand（只说「是登录页截图，含 2 个输入框」） | 像素 |
| write / edit | 不适用（本来就是写） | —— |

### 8.3 隔离强度必须由外部配置，不能由模型自选

**这是本节的核心判断。**

早期版本写的是「隔离强度由调用方按场景选」——也就是让模型自己决定
要不要隔离。这个设计不成立，理由三条：

1. **被约束方不能决定约束。** 模型是可能泄露数据的那一方，让它选
   隔离强度等于让被审计者自己定审计规则。
2. **模型不知道敏感边界。** 它看不到组织策略：哪些路径是生产的、
   哪个文件含密钥、哪个截图里有用户信息。
3. **它有反向激励。** raw 拿到的信息最全，往返最少。在没有外部约束时，
   模型倾向于选 raw。

所以隔离强度**必须是外部配置**，模型只能在该配置允许的范围内表达意图。

### 8.4 三层控制模型

```text
策略层（外部配置）  →  定义上限与规则，模型不可修改
        ↓
意图层（intent）    →  模型表达「我想要什么形状」
        ↓
执行层              →  实际生效 = 意图 与 策略上限 的交集
```

**实际生效档位 = min(意图档位, 策略允许的最高档位)**，再叠加路径规则。

### 8.5 配置形态

```yaml
isolation:
  # intent=auto 时的默认档位
  default: summary

  # 允许的最大暴露档位。intent 请求超过它时走回退链
  max_exposure: raw

  # 按路径的规则，优先级高于上面的全局设置
  rules:
    - glob: "**/.env*"
      level: none
    - glob: "**/secrets/**"
      level: none
    - glob: "**/*.pem"
      level: none
    - glob: "**/*.log"
      level: summary
    - glob: "**/prod/**"
      level: understand
    - glob: "**/*.png"
      level: understand      # 图片默认只给判定与坐标，不给原图

  # 请求超出上限时的回退链。从左到右尝试，第一个可行的生效
  fallback_chain: [redact, structure, summarize, refuse]

  # 脱敏后保留率低于此值时，视为「脱敏无意义」，继续下一级
  redact_min_retention: 0.5

  # 输出内容级规则（§8.11）。路径规则覆盖不了 bash/search 的输出，
  # 这一层按内容特征匹配，与上面的路径规则取交集。
  content_rules:
    - kind: secret_pattern
      level: redact
```

几条设计要点：

- **规则按 glob 匹配路径**，因为 read/write/edit 的输入就是路径，这是最自然的切面；**bash/search 的输出不适用**，需要 §8.11 的内容级规则补位；
- **规则可以比全局更严也可以更松**，但都不能突破 max_exposure 这条硬顶；
- **fallback_chain 可配**：不同团队对「宁可少给还是宁可给脱敏版」的偏好不同，
  默认链是「信息量优先」，可以整体改成保守策略（直接 refuse）。

### 8.6 回退链：降级是兜底，不是首选

**核心原则：每次降级前先问「有没有保信息的替代方案」。**

早期的设计是 on_exceed 二选一（downgrade 或 reject），把降级当成直接动作。
这是错的——降级会一次性丢掉全部内容，而很多时候只损失一小部分就够。

#### 四级回退，按信息量从多到少

| 顺序 | 动作 | 给什么 | 什么时候可行 |
|---|---|---|---|
| 1 | redact | 脱敏后的**原文** | 机械脱敏能定位敏感片段，且保留率 ≥ redact_min_retention |
| 2 | structure | 结构化骨架（类型、结构、关键项） | 内容是代码/配置/日志，可提取结构 |
| 3 | summarize | 摘要 | summarize 槽位可用 |
| 4 | refuse | 拒绝 + 说明原因 | 以上都不可行 |

#### 三个具体例子

**例 1：500 行配置文件里有 3 个密钥**

- 请求：raw
- 走第 1 级：脱敏后给全文，保留率 99.4%
- 结果：模型看到 500 行，只有 3 处变成 [REDACTED:AWS_KEY]

**例 2：.env 文件，12 行全是密钥**

- 请求：raw
- 第 1 级：脱敏后剩 12 行 KEY=[REDACTED]，保留率约 8%，低于阈值
- 走第 2 级：structure → 「这个文件有 12 个键，涉及数据库、AWS、Stripe」
- 结果：模型知道该去别处找具体值，也知道有哪些类别

**例 3：商业机密代码，无机械可识别模式**

- 请求：raw
- 第 1 级：脱敏没找到可抹的东西，保留率 100%——但内容整体敏感
- 这暴露了 redact 的局限：**它只能处理「可识别的敏感片段」，处理不了「整体敏感」**
- 所以路径规则（如 **/proprietary/** → understand）要先把这类文件拦下，
  不让它走到回退链

#### redact 的保留率判据

没有这个判据，对 .env 这种文件脱敏等于全抹掉，还不如直接结构化。

判据：脱敏后剩余字节数 / 原始字节数 ≥ redact_min_retention（默认 0.5）。

低于阈值说明「这个文件的主体就是敏感数据」，脱敏没有意义。

#### 为什么顺序是「信息量优先」而不是「安全优先」

因为过度保守的成本被低估了：模型拿不到内容就会猜，猜错会导致错误的修改，
修复成本远高于多给一点脱敏后的信息。

安全由**策略层**保证（max_exposure + 路径规则），回退链负责的是
「在安全边界内尽量多给」。两者分工明确。

### 8.7 回退必须显式告知

被回退时，返回里必须说清四件事，字段固定（渲染与预算见 §4.4b 的 `ISOLATION_FALLBACK`）：

| 字段 | 内容 | 例 |
|---|---|---|
| `requested` | 请求档位 | `raw` |
| `actual` | 实际动作 | `structure` |
| `rule` | 命中的规则（脱敏后） | `**/.env*` |
| `reason` | 为什么没用更高一级（枚举） | `retention_below_threshold` |

```text
[ISOLATION_FALLBACK] requested=raw actual=redact rule=**/config/** reason=redact_optimal
[ISOLATION_FALLBACK] requested=raw actual=structure rule=**/.env* reason=retention_below_threshold
```

`reason` 只写回退原因，不复制脱敏统计——脱敏结果由 `REDACTED` 单独告知
（count / retention）。`rule` 的脱敏见 §4.4b「敏感信息」。

**不告知等于欺骗**：模型会以为自己拿到了原文，基于不完整信息做决策，
然后在不该确定的地方确定。

告知里带「为什么没用更高一级」，模型才能判断「要不要换个方式拿信息」
（比如改读别的文件、或者问人）。

### 8.8 谁能改配置

| 角色 | 能否修改 | 说明 |
|---|---|---|
| 用户 / 管理员 | 能 | 通过配置文件或启动参数 |
| 调用方的 agent | **不能** | 不在 MCP 工具面里暴露任何写配置的能力 |
| 本地模型 | 不能 | 它只是被执行层调用 |

这条是硬约束：**工具层不提供任何「临时放宽隔离」的接口**。需要放宽时，
改配置并重启，让人来做这个决定。

### 8.9 与成本的关系

隔离不是越严越好。过度隔离会让云端瞎猜，产生更多往返，反而更贵。

所以默认配置应该偏宽松（`max_exposure: raw`、`default: summary`），
只在明确敏感的位置收紧。**把严格留给需要的地方，而不是全局最严**。

### 8.10 脱敏：机械能解决多少

隔离档位决定「传多少」，脱敏决定「传的内容里哪些要抹掉」。两者正交。

**脱敏优于降级**：一个 500 行的配置文件里有一个 API key，降级会让整个
文件不可见；脱敏只抹掉那一行。前者丢失 499 行的上下文，后者只丢 1 行。

#### 敏感数据的范围

「敏感数据」不只等于「密钥」。toolgate 的脱敏与隔离按以下类别覆盖（依据见
附件 E.7）：

| 类别 | 典型内容 | 主要检测方式 |
|---|---|---|
| 凭据与密钥 | 密码、API key、token、私钥、Cookie、连接串 | 格式正则 + 高熵 |
| 个人身份信息（PII） | 姓名、邮箱、电话、证件号、生日、地址、账号 | 正则 + 模型判定 |
| 金融与支付 | 银行卡 PAN、CVV、银行账户、薪资 | 格式 + 上下文 |
| 健康、基因与生物特征 | 诊断、用药、保险号、DNA、指纹、人脸 | 模型判定 |
| 特殊类别与未成年人 | 种族、政治、宗教、工会、性取向、犯罪记录、14 岁以下 | 模型判定 / 路径规则 |
| 商业机密 | 源代码、合同、客户名单、内部文档 | 路径规则 |
| 位置与会话标识 | GPS、EXIF、精确轨迹、session、cookie、设备 ID | 元数据 / 正则 |
| 路径与元数据 | 路径中的用户名、主机名、内网 IP、UNC 共享名、git remote | 路径 / 内容规则 |
| 图像内容 | 截图中的 token、证件、人脸 | OCR + 视觉判定 |

**分类不是互斥的**：同一段内容可能同时属于多类，按最高敏感度处理。用户名
本身可能不是秘密，但出现在路径、邮箱或账号里时能标识自然人，应按 PII 处理。

#### 机械能做什么

已知格式的密钥有稳定的字符模式，正则即可命中：

| 类型 | 模式（示例，实际需维护） |
|---|---|
| AWS Access Key | AKIA + 16 位大写字母数字 |
| GitHub PAT | ghp_ / github_pat_ + 长串 |
| GitLab PAT | glpat- + 20 位 |
| OpenAI / Anthropic | sk- / sk-ant- / sk-proj- + 长串 |
| Stripe | sk_live_ / pk_live_ + 24 位 |
| Google API | AIza + 35 位 |
| Slack | xox[baprs]- 开头 |
| JWT | eyJ 开头的三段 base64url |
| PEM 私钥 | BEGIN ... PRIVATE KEY 块 |
| 数据库连接串 | scheme://user:password@host |
| Bearer 头 | Bearer + token |
| 通用高熵串 | Shannon 熵 > 4.5 且长度 ≥ 20 且字母数字混合 |

最后一类是兜底：**不依赖格式，只看「像不像随机串」**。它能抓到没有固定
前缀的自定义 token，代价是可能误伤（比如长哈希、base64 数据）。

#### 机械做不到什么

诚实地说，**不能完全解决**。三类漏网：

1. **自然语言描述的凭据**——「密码是 hunter2」「这个服务的口令写在注释里」
   这类没有字符模式，正则抓不到。
2. **被编码或拆分的密钥**——base64 之后再 base64、或者拆成两行拼接，
   熵检测可能失效。
3. **上下文才构成敏感的内容**——不是「某个字符串是密钥」，而是
   「这段业务逻辑本身是机密」。这没有机械判据。

还有一类特殊：**图片里的密钥**。截图里的 token 需要先 OCR 才能脱敏，
成本高一个数量级，通常直接走 understand 档位（不给原图）。

#### 两层设计

```text
第一层：机械脱敏（必做，0ms，确定性）
  ├─ 已知格式规则表
  └─ 高熵串兜底
第二层：模型判定（可选，数十 ms，概率性）
  └─ classify 槽位判 sensitivity，命中则升级处理
```

**第一层必须永远开启**：它是纯正则，零延迟，收益确定。没有理由关掉。

**第二层默认关闭**：它要一次模型调用，且判不准。只在配置里显式开启，
用于高敏感场景。

#### 替换成什么

三种做法，各有代价：

| 做法 | 优点 | 缺点 |
|---|---|---|
| 整段删除 | 彻底 | 上下文断裂，模型不知道那里原本有什么 |
| 替换成 [REDACTED:类型] | 保留「此处有个 AWS key」的语义 | 泄露了类型 |
| 保留前后几位 sk-...abc | 便于人识别是哪个 key | 泄露部分内容 |

**推荐第二种**。保留类型信息对模型有用（它知道这里本该有个凭据、
不该去别处找），而类型本身通常不是秘密。

**不要用哈希代替**：低熵的密钥（如 6 位密码）可以被穷举反推。

#### 脱敏必须对所有权位生效

不只是 raw。summary 和 structured 的输出同样可能带出密钥——
模型摘要把 key 抄进摘要里是常见事故。

所以脱敏的位置在**工具返回之前**，对所有 intent 统一生效。

#### 可验证性

机械脱敏的好处是**可测试**：给定输入，输出确定。

所以规则表要配回归测试：每条规则至少一个正例（应命中）和一个负例
（不应命中）。这比「模型判定准不准」容易验证得多。

#### 与隔离档位的关系

```text
隔离档位：决定传多少（none / understand / summary / raw）
脱敏：   决定传的内容里哪些抹掉
```

两者叠加：先按档位裁剪，再对裁剪结果脱敏。

注意顺序——如果先脱敏再裁剪，被抹掉的部分可能影响摘要质量。这条只适用于**回传内容**；**落盘副本**的顺序相反，见 §8.12。

### 8.11 输出内容级隔离：路径规则覆盖不了命令输出

§8.5 的规则按 glob 匹配路径，它假设「工具的输入就是路径」。这个假设对 read/write/edit 成立，对 bash/search 不成立：

- bash 的输入是 `binary + args`，输出可以是任意文件的内容。`bash {binary:"cat", args:[".env"]}` 不会命中 `**/.env* → none`；
- search 的命中跨多个文件，输出里的每一行来自不同路径，无法套单一规则。

所以隔离需要两层：输入路径规则（§8.5）与输出内容规则（本节）。

```yaml
isolation:
  content_rules:
    - kind: secret_pattern          # 复用 §8.10 的规则表
      level: redact
    - kind: sensitive_path_mention  # 输出里出现 **/.env*、**/secrets/** 等路径名
      level: summary
    - kind: path_username           # /Users/<name>、/home/<name>、C:\Users\<name>
      level: redact
    - kind: host_metadata           # 主机名、内网 IP、UNC 共享名
      level: redact
    - kind: high_entropy            # 熵 > 4.5 且长度 ≥ 20
      level: redact
```

命中后按 `fallback_chain` 处理。`none` 档命中时按 §1.4.5 的 `IsolationRefused` 错误返回（fact：输出含受策略限制的内容；reason：命中输出内容级规则；nextSteps：调整策略或改用允许的路径），并附退出码、字节数、行数，不返回内容本身。`ISOLATION_FALLBACK.actual=refuse` 只用于回退链内的 refuse，不用于策略层 `none`。

#### 路径中的用户名与元数据

本地绝对路径是常见漏点，尤其在 bash 输出、编译错误、堆栈、git remote 和临时文件里：

| 形态 | 示例 | 默认输出 |
|---|---|---|
| macOS 用户目录 | `/Users/<user>/project/src/a.rs` | `<workspace>/src/a.rs` |
| Linux 用户目录 | `/home/<user>/project/...` | `<workspace>/...` |
| Windows 用户目录 | `C:\Users\<user>\project\...` | `<workspace>\...` |
| UNC 共享 | `\\host\Users\<user>\...` | `\\[HOST]\Users\[USER]\...` |
| 临时目录 | `/tmp/xxx`、`/var/folders/...` | `<tmp>/...` |
| Git remote | `https://<user>@github.com/org/repo` | `https://[USER]@github.com/org/repo` |

第一期只实现 macOS 与临时目录两行（§19.7）；Linux / Windows / UNC 行属后续平台规划。

**规则**：

- 模型可见路径默认一律工作区相对路径（`<workspace>/...`）；工作区外输出 `<external>/...`；
- 用户名段替换为 `[USER]`，主机名替换为 `[HOST]`，内网 IP 替换为 `[IP]`；保留结构，不保留身份；
- 把当前进程的 `$USER` / `$LOGNAME` / `%USERNAME%`、主机名作为运行时动态敏感词，按词边界替换；不能只依赖 `/Users/`、`/home/` 前缀。`whoami`、`hostname`、`git config user.*` 的输出同样处理；
- `none` / `understand` 档返回 opaque 句柄（`spill://<hash>`），不返回绝对路径；`raw` 档只有显式配置 `paths.expose_absolute: true` 才返回绝对路径，且仍要过 `path_username` 规则；
- 路径规则同时作用于 read/write/edit 的返回 meta、bash/search/task 的输出文本、错误 message 与 §4.4b 的 notice params（rule / pointer / failed），不能只作用于文件工具。

**边界**：内容级规则是启发式，不是完备的。它抓不到自然语言描述的凭据（§8.10 已列）。用户名匹配也可能误伤项目名，因此替换为 `[USER]` 后保留上下文，不做哈希（低熵用户名可被穷举反推）。它不能替代路径规则，只能补位。

### 8.12 本地副本：隔离模型之外的数据面

隔离四档约束的是「回传内容」。工具层还会在本地产生副本：

| 副本 | 落点 | 内容 | 谁看得到 |
|---|---|---|---|
| spill | 系统临时目录 | 截断后的完整输出 | 本机任何进程 |
| snapshot | 项目内 .toolgate/snapshots | 改动前的旧内容 | 本机任何进程 |
| 摘要缓存 | 缓存目录 | 摘要结果 | 本机任何进程 |
| 图片缓存 | 缓存目录 | base64 与元信息 | 本机任何进程 |

**这些副本不在模型可见路径上，但仍在数据面上。** 如果落盘发生在脱敏之前，磁盘上就有明文密钥，而「不泄露给未授权方」的承诺会被解释成「不出机器」，不是「不出进程」或「不给模型看」。

#### 统一流水线顺序

```text
执行 → 全量机械脱敏（§8.10）→ 落盘（全量脱敏副本）
     → 有界候选窗口（§9.3、§6.4）→ 本地模型读窗口做摘要 → 摘要再脱敏
     → 返回 content + 指针
```

**spill / 摘要缓存 / 图片缓存的落盘副本一定是脱敏后的**。如果摘要需要看未脱敏的原文，只在内存里看，不落盘。

**快照是唯一例外**：快照保存原始字节、不脱敏，权限 0700/0600，只用于回滚。它不进入模型可见路径，也不承诺可跨用户共享；回滚的语义是「把用户自己的文件恢复到改动前」，所以保真优先于脱敏。若策略要求快照也不得含敏感内容，替代方案是加密落盘（密钥管理会引入工具层，成本更高）。

#### 权限与生命周期：谁产生谁清理

- 目录 0700、文件 0600；
- **每个持久化副本由产生它的工具登记并按自己的策略清理**；调用方不承担清理责任，也不存在跨组件的全盘清理脚本。

| 副本 | 产生者 | 清理责任 | 默认保留 |
|---|---|---|---|
| spill | bash / read / search | spill GC | TTL 7 天；每工作区 1GB；超限 LRU |
| snapshot | write / edit | snapshot GC | 每文件最近 20 份；至少 24h；最多 30 天；每工作区 1GB |
| 摘要缓存 | summarize 槽位 | cache GC | 容量上限 512MB；超限 LRU |
| 图片缓存 | 图片流水线 | cache GC | 容量上限 512MB；超限 LRU |

**快照状态机**：`tmp → active → expired`。write/edit 先写临时文件，fsync + rename 后登记 `index.jsonl`；写失败则不修改原文件。`min_retention_hours`（默认 24h）内不清理；达到 `keep_per_file`、`ttl_days` 或 `max_bytes` 水位时，由后台 GC 从最旧且已过保护期的条目开始淘汰。回滚进行中的快照带 lease，GC 跳过；回滚本身也产生新快照，不删除旧快照。快照过期后回滚返回 `SNAPSHOT_EXPIRED`，不静默失败。

**GC 是旁路，不在工具请求链上**：workspace GC 调度器运行在独立线程/任务组；工具路径不做同步淘汰。创建快照前只做一次 O(1) 的 `statvfs` 空闲空间检查：低于 `min_free_bytes`（默认 512MB）时返回 `SNAPSHOT_QUOTA_EXCEEDED`，不写原文件；正常情况下不等待 GC。GC 队列满时丢弃本次 hint，由周期巡检兜底。

**触发者与时机**：由 toolgate 进程内的 **workspace GC 调度器**触发；各产物产生者注册自己的清理 handler 与策略，调度器只按产物类别调用，不跨类别删除。调用方与模型不触发清理。

- **启动**：服务就绪后后台跑一次过期项、临时残留与索引修复；
- **写入后**：producer 只投递低优先级 GC hint，不等待结果；
- **周期**：每 `gc_interval_hours` 后台巡检 TTL 与容量；
- **配额**：`max_bytes` 是后台 GC 的目标水位；工具路径只做上述 O(1) 空间检查，不触发同步淘汰；
- **手动**：CLI `toolgate gc` / `toolgate snapshot prune`，供运维与 cron 使用，不新增 MCP 工具；
- **多实例**：同一工作区用 `gc.lock` 选出本轮执行者，各 handler 只处理自己类别的条目。实例崩溃时，已完成的产物按 TTL 处理，`*.tmp` 由下次启动清理，不因进程退出立即删除。

**调用方**：只拿快照路径用于回滚，不负责清理。

`none` 档不落盘：只返回元信息（存在性、类型、大小），不写 spill。

#### 路径本身也是信息面

回传绝对路径会泄露目录结构、用户名、项目名。模型可见路径默认一律工作区相对路径（`<workspace>/...`）；工作区外用 `<external>/...`。用户名段替换为 `[USER]`，主机名替换为 `[HOST]`，内网 IP 替换为 `[IP]`。`none` / `understand` 档用 opaque 句柄（`spill://<hash>`）；`raw` 档只有显式配置 `paths.expose_absolute: true` 才返回绝对路径，且仍要过 `path_username` 规则。
