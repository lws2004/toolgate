# toolgate 重新定位提案（2026-11-14）

> 本文件是**重新定位的提案 / 评审输入**，不是权威正文。评审通过后按 §3.6 的流程落回
> [architecture.md](architecture.md) 与分册。提案不改变当前实现，只重定义目标。
>
> 触发：用户重新标定架构目标——从「数据不出本地 / 省 token」转向「agent 增强」。
> 四项已定决策见 §3。

## 0. 一句话

toolgate 从「MCP 工具供应商」重定位为「**agent 内置工具的感知增强层**」：agent 照用
它自带的 read / bash / edit / search，toolgate 在工具结果**进入 agent 上下文之前**拦截、
理解、治理，再把增强后的形状交还。理解用哪里的模型不重要（本地 SLM 或 agent 会话模型
皆可），**产出**才重要。

## 1. 为什么旧命题要退役

旧 v2 的价值锚是 §1.1「理解应该发生在数据离开本地之前」——价值 = ① 省 token ② 数据不出
本地。它失效率于三个前提：

1. **落点放错了。** 真正有效的边界是「结果进入 agent 上下文之前」，不是「出本地之前」。
   只要理解发生在「进上下文前」，用本地小模型还是 agent 的云端模型，对 agent 看到的形状
   没有区别。
2. **赌注过高。** 它把架构绑死在本机 SLM 性能上（Apple Silicon 上 summarize 50KB ≈ 7.6s，
   见 §3.1 实测口径）。本地模型一弱，整层价值塌方。
3. **接入形态制造歧义。** §18.6 自陈「做成同名工具会制造选择歧义」——让 agent 在「内置
   read」与「toolgate read」之间选，本身就是负担。

新命题（可证伪）：

> **工具返回在进入 agent 上下文之前，应被压成 agent 能直接决策的形状。**

## 2. 增强的意义（本提案的核心）

价值公式从「挡住的 token 数」换成「**降低 agent 的无效动作**」。增强增强的不是
「数据的位置」，是「**agent 的输入质量**」。六条，每条对 agent 可感：

| # | 意义 | agent 侧的证据（可证伪指标） |
|---|---|---|
| 1 | **高信噪比** | 同一上下文预算里，返回带的信息更决策相关；不是更少 token，是更准。指标：达成同一任务所需上下文占用下降。 |
| 2 | **结构化可用** | 返回是带 `errorCode` / `meta` / `nextSteps` 的结构，程序可分支，不必「读懂文本再写 Regex」。指标：调用方按字段决策的比例。 |
| 3 | **错误可行动** | fact / reason / nextSteps 三段，不猜、不盲重试（§1.4.4）。指标：错误后「重试同一调用」的比例下降。 |
| 4 | **状态可编程** | 判定出确定枚举（构建失败 / 3 个测试超时 / 通过），调度程序可据以下一步。指标：任务调度分支的正确率。 |
| 5 | **写安全** | 写前版本指纹复核 + 快照，连 agent 内置 write / edit 也不破坏文件、可回退（写侧 pre hook 的落点）。指标：被破坏文件数 = 0。 |
| 6 | **跨宿主一致** | pi 的 8 个工具、dsh 的十几个工具返回形态各异，增强层归一成同一套语义。指标：换宿主后调用方无需改解析逻辑。 |
| 7 | **持续处理能力** | 进上下文的信息经过精简，同一上下文预算能承载更长的任务 / 更多轮，agent 能一口气处理更久。指标：完成任务前的有效轮数上升、上下文触顶次数下降。**前提：精简不得丢关键信息——质量必须保住或提升，否则是有损截断不是增强**。 |

**关键推论（定位翻新的实质）：「理解发生在哪里」与「理解产出」解耦。**
v2 把两者绑死（理解必须在本地 → 才省 token 才有价值）；新定位解耦——理解可外包给 agent
的会话模型，价值只在产出。这使架构不再依赖本地模型强弱，也让「会话模型充当摘要」（用户
补充）成为一等公民而非权宜。

**省 token 仍是并列目标，不是副产物**（按重新定位讨论修正，理由成立）。机制变了：

- v2 的省 = 「数据不出本地」→ 原始返回不传给云端规划模型；
- 新架构的省 = 「进上下文的是压缩后的最小形状」——更直接、更可控；
- 成立条件（两条同时满足，均可由配置达成）：
  1. **产出简化是主体**：简化省的 token > 结构化附加（meta / notices / nextSteps）花的 token，
     净省 = Δ简化 − Δ附加，设计上保证为正；
  2. **增强调用是「隔离微调用」**：每次增强只喂**一条工具返回**，不带会话历史、无长文干扰——
     输入 compact、成本低、质量高（不被前文噪声带偏）。用哪个模型由**调用方配置（配置提供
     默认）**：本地 / 廉价模型 → 成本 ≈ 0；会话大模型同样可用，因为它是单条变换、不是重跑会话。
- **省是复利的**（最易漏的一条）：工具返回一旦进上下文，之后**每一轮**都被重复 prefill（§1.4）。
  把 T_in 压成 T_out，省的是「轮数 × (T_in − T_out)」，远超一次性增强的 2·T_out 开销；只有
  「单轮且原文很小」才可能不划算——而那种返回本就不该触发增强（形状路由按阈值直接放过），
  即「不值得增强的就不增强」。
- 一句话：**把增强模型来源做成配置项、默认压到低成本，省 token 就是默认可保证的目标**；
  调用方选贵模型换质量时才放弃它。

**数据不出本地**仍是**部署选项**（loopback 网关 = 本地；反向委派 agent 模型 = 云端），
按场景选，不再是硬约束（用户已明确「不必纠结」）。

## 4. 接入形态

- **固定 Rust daemon**：常驻、多 agent 共享一个实例，本地回环 HTTP / Unix socket 上跑
  `govern` 增强服务；**核心仓零框架代码**（决策 2）。替代「每 agent 拉一个 stdio server、
  随 agent 起停」。
- **薄适配器（独立仓，一期 pi / dsh）**：挂宿主接缝 → 转 `govern` → 写回；零执行逻辑，
  不含任何工具实现。
- **接缝点（已取证，非设想）**：

| 宿主 | 读侧（可改返回） | 写侧（可 block） |
|---|---|---|
| dsh | `tools/post-execute`（accept / replace / enrich / block，见 `packages/core/tools/src/events.ts:41`） | `tools/pre-execute`（block / ask，`events.ts:18`） |
| pi | `afterToolCall`（整段替换 content / structuredContent / details / isError，见 `pi-agent-core/dist/types.d.ts:53-107`） | `beforeToolCall`（block，`types.d.ts:44`） |

> 校勘：现 §18.7 的「客户端钩子」表把 dsh 写成 `tool/result`——那是 `emit` 只读、改不了
> 结果，应订正为 `tools/post-execute`；pi 的「MCP result adapter」应订正为 `afterToolCall`。

## 5. 处理器路由：按「内容形状」而非「工具名」（免白名单）

对外不再有「六个工具」，也**没有「要增强哪些工具」的登记表**。增强层**不登记工具，只观察
调用**——这是「中间件 / 观察者」范式，不是「白名单 / 注册表」范式。三段实现：

### 5.1 截获：全局管道，天然覆盖所有工具

dsh 的 `tools/post-execute` / `tools/pre-execute` 是**每一次工具 dispatch** 都过的统一
waterfall；pi 的 `afterToolCall` / `beforeToolCall` 是 agent loop 里**每一次工具调用**的
钩子。调用一发生钩子必过，所以**不需要知道某 agent 装配了哪些工具，也不需要预先登记**；
将来新增的工具（如某 agent 的 `notebook_edit`）自动被覆盖。不同 agent 工具集不同这件事，
在截获层就消解了——因为它是事件驱动，不是集合枚举。

### 5.2 路由：按返回形状，不按工具名

处理器按「返回是什么形状」分派，与工具名解耦（这正是 §3.1「六槽位按答案形状分」的落地）：

| 观察到的形状（确定性 L0 嗅探） | 分派到 | 动作 |
|---|---|---|
| 含 image block / 图片魔数 | vision | 压缩 + OCR / 描述 + 判定 need_pixels |
| 超长文本 / ANSI 日志 / 行缓冲 | summarize | 双阈值截断 + 落盘指针 + 摘要 |
| 错误标记（isError / exit≠0 / stack） | 可行动化 | fact / reason / nextSteps 三段（§1.4.4） |
| 大量行列表 / 命中清单 | rerank | 按意图重排 + 截断 |
| 已是结构化 JSON（带 outputSchema） | 归一 | 保留结构，仅补 meta / notices |
| 二进制 / 未知 MIME | 元信息 | 路径 + 类型 + 大小，不瞎解析 |

三级信号叠加，越靠前越确定：① 确定性命中（魔数、字节数、错误位）→ ② 返回自带
`structuredContent` / `outputSchema`（dsh / pi 每个工具都声明，是最准的形状来源）→
③ 形状仍模糊才交 classify / decide 按内容判。**判定依据始终是「内容」，不是「这是哪个工具」。**

### 5.3 兜底：形状不识别 → 退回纯 L0 治理

不认识的返回只做机械治理（截断 / 落盘 / 脱敏 / 错误可行动化），不瞎摘要。与 §3.8「槽位
全空仍可用」同构：**未知形状不会出错，只是增强得少**。这条保证「免白名单」不会变成
「免责任」。

### 5.4 写侧 pre 的「读写判断」

写侧门控对误判敏感。顺序：① 用工具定义的副作用 / 并发安全元信息（dsh `isConcurrencySafe`、
工具声明）→ ② 按参数结构（path + 写语义）→ ③ 不确定时**保守按写处理**（宁可多跑一次
只读复核，不可放过写）。

> **典型来源只作参考，不作路由依据**：read→图像 / 文本分级、bash→日志 / 错误、grep / find→
> 命中清单、edit / write→写侧复核、dsh job_output→增量摘要。这些是「常见形状出现在哪个
> 工具」，路由仍看形状。
>
> **诚实边界**：领域专用返回（某 agent 的 `db_query` 表格）通用处理器只做机械治理，深加工
> 要领域适配——那是可选增强，不做也不错，不构成白名单门槛。
>
> **现实缺口**：pi 只有 8 个平铺工具、无 search 聚合、无 task（`research-notes-pi.md`）。
> 形状路由照样工作（grep / find 的命中清单会被 rerank 接住），只是 pi 侧没有「task 状态」
> 这种形状可判。

## 6. govern 协议三块

1. **读侧治理**：现 §18.7 的 `govern` 从「web_fetch 治理」扩为「全部内置工具结果」，处理链
   复用 §4.8 理解链，intent 作为策略参数。
2. **写侧 pre**：新增 `pre` 接口——在 agent 内置 write / edit 执行**前**拦截，取当前真值做
   (mtime,size,sha256) 复核 + 写前快照，可 block 并回 fact/reason/nextSteps。
3. **反向委派**：daemon 需要某槽位且本地 SLM 不可用时，回一个「委派请求」给适配器，适配器用
   **调用方配置的模型**（默认配置的廉价模型，可显式指定会话模型）执行后回填。**成本口径**：这是
   一条**隔离微调用**——只喂该条返回、无会话历史；压缩后的 T_out 还省掉后续每轮重复 prefill，
   多轮场景净省远大于一次性开销。§6.2 按「净省 = Δ简化 − Δ附加 − 增强模型成本（含轮数复利）」
   核算。
