# ADR 0004：本地小模型属于工具层，不是可选增强

- 状态：已采纳（推翻了 v1 的判断）
- 日期：2026-11

## 背景

v1 版本把「本地 LFM3 摘要」与「d1 快思考路由」移出了工具层，理由是
「工具层无状态、不该调模型」。

用户指出：**充分利用本地小模型是核心架构理念，要围绕本地小模型构建工具**。

## 决策

推翻 v1 的判断。本地 SLM 是工具层的一部分，每个工具内部有
「执行 → 理解 → 协商」三层，理解层由本地 SLM 承担。

## 三条理由

**1. 延迟。** d1 单次决策 5.7ms。跨进程调用本地模型要多一次 IPC，
IPC 开销可能比推理本身还大。放在工具进程内才划算。

**2. 数据。** 如果 SLM 在外部服务，原始数据要先出工具层再回来，
「数据隔离」的前提就没了——而隔离正是这套架构的主要收益之一。

**3. 判据。** 什么时候该调模型，取决于工具的上下文（输出多长、什么类型、
命中多少条）。外部服务看不到这些，只能靠调用方传，等于把判断推回给云端。

## v1 错在哪

把「工具层不该有状态」与「工具层不该调模型」混为一谈了。

- 不该有**会话状态**（跨调用的记忆）——这条成立，因为工具层看不到
  目标与步数；
- 不该调**模型**——这条不成立。调模型不需要状态，只需要输入。

LFM3 与 d1 都是无状态的：给输入，出输出。它们不破坏工具层的无状态性。

## 代价

- 工具层现在依赖本地推理后端（llama.cpp / MLX / vLLM），
  部署复杂度上升；
- 必须实现降级路径：模型不可用时静默回退到纯执行模式；
- 需要置信度门控，否则小模型的错误会污染整条链路。
