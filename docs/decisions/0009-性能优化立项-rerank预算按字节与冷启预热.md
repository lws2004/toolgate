# ADR 0009：两项性能优化的后续立项（rerank 预算按字节估算、daemon 冷启预热策略）

- 状态：P1 已实现（2026-11-15）；P2 已评估并否决大样本预热（实测有害），保留轻量预热
- 影响面：未来可能改 `govern.rs` 的 `rerank_estimated_ms` 预算函数与 daemon `local_slots.rs` 的 `prewarm` 策略；**当前不改**任何对外契约、默认行为与红线
- 触发：R12 交付与独立复审确认两处真实成本问题，但都不在「遗留清理」范围（一个改预算语义、一个是部署/运维策略），故立项为独立后续工作

## 背景

R12 与历史实测暴露两处成本问题，均只影响性能边界、不影响正确性：

1. **rerank 预算按条数估算，未计行长。** `rerank_estimated_ms = 100 + 15 * lines`（`crates/toolgate-core/src/govern.rs`）只看候选条数。少行而单行很长的列表会低估耗时：120 行 × 约 330B（≈39 KiB）无 `query` 场景实测 4952ms，超出名义 2s 预算（`reports/bench-r10-2026-11-15.txt`）。因 39 KiB > 32 KiB 不满足「小列表无 query 跳过」，仍进 rerank。
2. **daemon 冷启首请求长。** `crates/toolgate-daemon/src/local_slots.rs` 的 `prewarm()` 只送 `"预热"` 8 `max_tokens` 的小样本，仅暖连通与权重加载，不暖大批量长输入。daemon 重建后首个 4000 行 / 157 KB 唯一长文的 summarize 首请求 19.4s，热态 946ms。预热在后台线程、不阻塞监听，但覆盖不到冷启主成本。

## 决策

分别立项为两个独立后续工作，本轮不实现。各自范围、约束、验收如下。

### 立项 P1：rerank 预算按字节估算

- **目标**：估算式纳入字节维度（如 `100 + 15*lines + k*bytes`，或对正文字节设阈值），使长行小行数列表不再超名义 2s 预算。
- **约束**：不改候选上限 `RERANK_CANDIDATE_LIMIT=1000`、不改默认 `RERANK_BUDGET_MS=2000`（只改估算函数）；不放松「≤max_lines 且 ≤32 KiB 且无 query → 原样返回」的跳过语义；`rerankChunk` 语义不变。
- **验收**：120 行 × 39 KB 无 query 用例要么走毫秒级兜底、要么估算 >2s 不重排；R10/R12 全部列表用例回归通过；`cargo test --workspace` 全绿；§4.0a 与测试报告同步更新。
- **为何现在不做**：改估算函数会移动所有列表重排的触发边界，属「改预算语义」，超出 R12 遗留清理范围。

### 立项 P2：daemon 冷启预热策略

- **目标**：降低 daemon 重建后首个大请求的冷启延迟（如预热一次中等长度 summarize 请求，或把预热与首个真实请求的可观测指标挂钩）。
- **约束**：预热不得阻塞 daemon 监听（现状已后台线程）；须评估每次重启的额外启动成本与对本地模型压力；不引入新依赖。
- **验收**：给出重建后首个大请求冷启延迟的前后对比与目标阈值，热态不回退；`GET /health` 正常；预热开销有记录。
- **为何现在不做**：属部署/运维策略，需隔离实测 + 启动开销权衡（tool-adoption-eval 式流程），非一行代码可覆盖。

### P2 实测结论（2026-11-15，已实施并否决大样本方案）

实测否决了大样本预热（`reports/bench-p13-2026-11-15.py`，daemon external-protocols，重启后立即发首个 157 KiB 长文请求）：

- 大样本预热（1500 行 ≈43 KiB、max_tokens 256）：首个请求 **38647ms**；
- 轻量预热（8 token，原方案）：同条件 **1498ms**（模型服务热态），热态 963ms。

原因：本地 summarize 实例内推理串行（§18.1 第 4 条），大样本预热占用推理线程，与紧随的首个真实大请求排队竞争，反而抬高首请求延迟；且 daemon 重启不重置外部模型服务，冷启主因在模型服务首次加载权重（8-token 轻量预热已能触发加载），不在 daemon 侧样本大小。**结论：保留轻量预热，不采纳大样本预热；P2 关闭为「已评估」。** 若仍需消除模型服务首次加载延迟，属模型服务层（llama.cpp / vLLM 预热），不在 toolgate daemon 侧。

## 代价与权衡

- 不立项：两处成本会被反复观察却无人认领，报告 §五 与 §4.0a 的「已知边界」长期悬挂。
- 立项但当前不实现：R12 默认行为不变、无回归风险；两者都只影响性能边界，不影响正确性。

## 边界

- 两项均不触碰 §2 红线，不改工具数量、槽位契约、隔离/脱敏档位。
- P1 属实现细节（§3.4），但因其移动触发边界，先立项 + 文档再实现更稳；P2 属部署层。
