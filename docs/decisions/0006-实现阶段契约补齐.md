# ADR 0006：实现阶段补齐四处契约空白

- 状态：已采纳（2026-11-09）
- 影响面：对外契约（错误码值域、决策表输入形状）、文档一致性
- 触发：实现阶段（§14 阶段 1）连续五轮暴露的 4 处契约空白；用户 2026-11-09 授权「补后执行」

## 背景

架构文档 v2 已定稿并签收（P0/P1 清零），但进入实现阶段后，实现者连续发现 4 处
「正文写不下去了」的地方：错误码值域不足、决策表签名漏列回退链输入、
两个通道的脱敏口径互相冲突、d1 调用形态仍标着「需要实测选定」。
若放任实现者自行补齐，等于把架构决策下沉到代码，违反 §3.2「架构未写下来的行为不得实现」。

## 决策

1. **ErrorCode 扩为封闭 12 个**：保留原 8 个特定场景码，新增
   UNKNOWN_TOOL / BAD_ARGUMENT / IO_ERROR / FAILED 四个通用兜底码；
   ToolError::UnknownTool 补 code 与 next_steps。§2 红线 7 对四个变体一律成立。
2. **§4.5 写全 decide_output 的 Rust 契约**：DecisionInput 显式纳入
   fallback_chain 与 redact_min_retention，DecisionOutput 明确
   output_shape / fallback_steps / decision_notices / meta；三段决策判据与
   intent→档位映射写成可执行规则。
3. **§4.4b 明确脱敏口径**：「原样携带」指不另写文案，不是绕过脱敏；
   rule 在 notice 构造时脱敏，content 与 structuredContent 拿到同一份已脱敏 notices。
4. **§13.4 定案**：删「需要实测选定」；阶段 1 以方案 A（每工具单独调 d1）为默认并预留
   turn 聚合钩子，方案 B 随阶段 1.5 兼容层与阶段 4 落地，不传 turn 字段永远退化为 A。

## 后果

- 正面：实现不再需要自行发明契约；红线 7、§15.7 属性测试口径可逐条落地。
- 代价：ErrorCode 值域扩大属对外契约变更，按码分支的客户端需同步；
  §4.5 输入参数比原文字签名多 3 项。
- 不改动：§2 红线本身、六个工具数量、只依赖 MCP 协议、五个槽位可空、最少依赖、
  工具层无会话状态、隔离强度由外部配置、依赖分层与部署形态。
