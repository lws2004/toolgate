# ADR 0001：不基于既有 agent 框架构建

- 状态：已采纳
- 日期：2026-11

## 背景

原始设计文档写「Rust Core，基于 rpi 构建」，并引用 rpi-plugin-sdk。

核实结果：

- 本机 ~/.local/bin/rpi 是 bash 脚本，exec 一个不存在的 ~/.local/bin/pi-rust；
- 项目真实存在（Dicklesworthstone/pi_agent_rust，1959 stars）；
- 另有同名项目 bigfish1913/pi-rust，其二进制才叫 rpi，且有 rpi-plugin-sdk。

即：可用作地基的候选有两个，且都不是「rpi」这个名字的唯一所指。

## 决策

不基于任何既有 agent 框架构建。只把 pi 与 DSH 当作**参考实现**读，
不引入其运行时。

## 理由

1. **耦合成本**：基于框架意味着继承它的工具注册模型、会话模型、
   扩展 ABI。而 toolgate 的目标是「不绑定任何 agent 框架」——
   基于某个框架构建直接违背这条。

2. **接口面足够小**：toolgate 对外只有 MCP 一个协议，对内只有
   6 个工具。自己写一遍的成本远低于适配框架的成本。

3. **可验证性**：41 个测试全部是纯 Rust，不依赖任何外部运行时。
   基于框架则测试要拉框架起来。

## 代价

- 需要自己实现 MCP 传输（已实现，约 200 行）；
- 需要自己实现截断、落盘、图片压缩（已实现）；
- 失去框架提供的会话、扩展、多 provider 支持（这些本来就不归工具层）。
