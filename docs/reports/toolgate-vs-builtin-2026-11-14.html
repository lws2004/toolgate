一、结论摘要

核心结论：toolgate 在 edit（行锚点/整段 diff）、task（后台长任务）、大输出落盘 spill、本地摘要/看图/结构化判定 上明显强于内置工具。相较上次评估，两个关键短板已改善：六工具固定定义从 8036B 瘦身到 5999B（1499.75 tok，按 4B/token 折算），首次落入 6000B / 1.5K token 红线内；400 行日志摘要端到端从约 25.8s 降到 3.7s。仍存的短板是：无 shell（bash 表达力受限）、大文件 auto 判定链路过慢（Cargo.lock 19.7s）、task kill 后状态展示不同步（进程已死仍显示运行中）、以及 默认构建（无 external-protocols）六槽位全部不可用，需 feature 重建。适合作为「重活 / 敏感数据不出本机」的补充工具层与内置工具并存，而非全面替换。
最关键的三条实测：① 固定开销达标——scripts/measure_tools.py --json 实测中文 full_result=5999B / est_tokens_4b=1499.75 / ok=true；② 摘要提速——read 400 行 intent=summary 端到端 3.715s（上次约 26s）；③ 默认 intent=raw 不摘要、不标注（设计如此，§5.1），须显式 intent=summary/auto 且输出 ≥500 token 才触发。

六、关键风险与限制

① 无 shell（安全设计，也降低通用性）：toolgate bash 拒绝 sh -c，不支持管道/重定向/变量展开；复杂 shell 组合必须改用内置 bash。
② 大文件 auto 判定过慢：Cargo.lock 类大文件 intent=auto 端到端 19.7s（decide+summarize 双链路）；高频大文件读取不宜用 auto，改 raw 或分片。
③ task kill 状态不同步：kill 请求后进程确实被杀（实测 0.5s 内 pid 消失），但 task list 持续显示"运行中"，3/5/8s 均不更新为"已退出"——基于 list 状态做编排会误判，需自行核对进程存活。
④ 默认构建槽位全不可用：无 external-protocols feature 的默认二进制六槽位全部 unavailable（no_client），必须 feature 重建才能用本地模型层。
⑤ 默认不摘要：intent=raw 为默认，须显式 summary/auto 且输出 ≥500 token 才触发。
⑥ 判定置信偶低：decide/classify 对模糊或高危输入给 LOW_CONFIDENCE（实测 0.01–0.07），需调用方容忍降级与机械保底。
⑦ 部署依赖：summarize 依赖 LFM2.5:10031、vision 依赖 MiniCPM-V:10014、decide 依赖 d3-nano:8082（该实例未加载 mmproj，带图判定不可用）；须三者常驻，否则槽位降级。
⑧ search files 受 .gitignore 约束：files 模式遵守 .gitignore，仓库若忽略 *.log 等类型，这些文件不会出现在结果里（实测漏掉全部 .log），需注意检索遗漏。
⑨ rerank query 复用：同一 query 既作正则又作 rerank 语义查询；关键词/正则作 rerank 语义弱，可能把最相关命中排到末位，务必用自然语言整句。
⑩ classify 会漏判：d3-nano 对邮箱 / API key 样本判 normal，输出标注取「classify 与机械正则更高等级、机械保底」；正常文本不受影响。
