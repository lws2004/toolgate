01 机制：成立，且已在真实链路闭环

  • 治理对象是 content（模型可见投影），不是 PTC 内层 value；适配器挂 post-execute 治理前者。
  • 嵌套调用跳过 /govern（内层 38ms，旧行为约 10.7s）。
  • 降级链 local → delegated → L0 三档，policy.slmPrefer 可切；本地槽位现已在这条链上。
  • 错误转发保真：fact/reason/nextSteps 只进 structuredContent.error。

02 作用评估：四个象限（本轮实测口径）

高收益 / 可接受成本 正收益

  • 长文本（约 8–32KB）：本地摘要 0.4–0.7% 输出、2–3s 级延迟，是稳定的正收益场景。
  • 需要语义排序的多文档候选：rerank 有价值；R9 起可按请求 query 定向保留，候选 ≤1000。
  • PTC 嵌套跳过：38ms，只在结果真正进模型时治理一次。

高收益 / 高成本 注意

  • 超大长文（180KB 级）：先采样 32KiB 再摘要，2200 行 4.2s；不采样则更慢。
  • 600 行 summary：R10 采样后仅 2.5s（原 35.3s）——已转为可接受成本。

低收益 / 高成本 注意

  • 短错误：分类命中但正文保真、0% 压缩；价值在可归因不在瘦身。
  • 60 行短列表：R10 已改为无 query 时跳过 rerank（1ms）。

低收益 / 低成本 正收益

  • 结构化 JSON：只补 meta/data，≈1ms。
  • 列表超 1000 行：毫秒级兜底（2ms），不请求模型。

04 已完成 / 待办

已完成 11-14 版 P0 建议全部落地

  • 列表治理 2s 预算 + 确定性兜底（超 1000 候选毫秒级，不再白等模型）。
  • 长文先采样再摘要（>64KB 先采样到 32KiB；intent=summary 放宽 120KiB；完整原文落盘回指针）。
  • /stats 可观测性（按 shape 的请求数/字节/耗时）与结构化治理日志。
  • 额外：本地槽位入链（R8，含 embedding 长文去重）、列表按请求 query 排序（R9，三态 + DEGRADED 告知 + query 作为数据字段）。

已完成 R10 治理时间预算优化

  • 长文摘要延迟：采样触发线 64KiB→32KiB、取消 summary 放宽 120KiB；600 行 40.4s→2.5s、1000 行 42.1s→2.2s。
  • 小列表无谓重排：无 query 且 ≤32KiB 的小列表跳过 rerank（60 行 448ms→1ms）。

待办 剩余短板

  • vision 本地未接：受「图片只传引用」限制，除非宿主提供像素或本地解码，否则维持 L0/委派。
  • 第三级 classify 偶发误判：实测 60 行 info 日志在 intent=debug/summary 时被判 long_text 并摘要为空（45B），raw 正常透传；需加确定性护栏，列为下一个独立主题。

不做 明确不在本期

  • >1000 行列表分段 rerank：成本约 35–40s（1000 docs≈11–13.6s×3）远高于 2s 预算，维持毫秒级兜底不排序。
  • 不为「槽位齐全」而接 decide / vision；decide 属工具判定用途，不在 govern 链。
  • 不为 query 单独写 ADR（向后兼容的可选字段，§18.7 已记录契约）。

05 边界与风险

  • 冷启：本地 summarize 首次曾 23.5s；daemon 启动后台预热已缓解，重启后首个大请求仍可能长等待。
  • 长文硬上限：超大输入必须先减输入，只调超时会拉长等待；R10 采样固定 32KiB（头+关键行+尾），完整内容走落盘指针。
  • rerank 服务端 1000 docs 上限：daemon 按 1000 分片串行合并分数。
  • 短错误不省字节、结构化 JSON 不压缩：均为有意的正确性/契约选择。
  • 单机单次实测，非吞吐/并发结论；平台仍为 macOS 第一期。
