结论
  • 本地 6 槽位已真正接入 govern 降级链：summarize（qwen3.6-35B-A3B）、rerank（jina-reranker）、classify（d3-nano）在正式 daemon 下 meta.slmStatus 报 local 并实际改写了输出；同一二进制在无配置环境（HOME=/tmp/tg_nohome，本地槽位 None）时这三类降级到 L0。
  • vision 槽位本地未接：process_vision 只走反向委派 / 元信息档，LocalSlots.vision_text 从未被调用；且图片只传引用不传字节，本地视觉模型拿不到像素，故 A/B 两态一致（都 unavailable）。
  • decide / embedding 不属 govern 链（分别用于各工具判定与检索重排），本表不体现其差异。
  • slmPrefer 生效：delegate 偏好下改走宿主会话模型（stub 实测 144B，slmStatus.summarize=delegated），与默认本地优先（203B，local）分流清晰。
  • 包装对真实会话已生效：本会话中 agent 的 bash/read 输出被自动治理成中文摘要（多次观察），侧证 dsh 薄适配器已挂载运行。

三、发现与边界

  • 本地 summarize 冷启与超时已收敛：旧测首次 23.5s，116KB 长文曾触发 30s 客户端超时降 L0。现已：daemon 启动后后台预热 summarize（不阻塞监听）；summarize 单请求超时放宽到 120s（classify/decide 仍 30s）；适配器 daemon 往返超时 8000→30000ms，避免 daemon 还在计算就被 failOpen 透传。复测 2200 行 / 约 183KB 长文：17.4s、335B、slmStatus.summarize=local。
  • 本地 rerank 输入上限已修：jina 服务端单请求 1000 docs 上限（3000 docs 直接 HTTP 400）；daemon 现按 1000 分片串行、按全局偏移合并分数取前 limit，单批超时 180s。复测 3000 行列表：19.5s、slmStatus.rerank=local、输出 2000 行（受 max_lines 上限）。大列表仍有 20s 级等待，属本地重排吞吐边界（估算：线性于批数，非链路失败）。
  • 链接器错误已纳入确定性错误路由：looks_like_error 新增 /usr/bin/ld:、ld:、undefined reference to、collect2: 前缀。复测无 error: 前缀的链接失败：isError=true、原文逐字保留 102B，fact 归因 collect2: error: ld returned 1 exit status。
  • 本地 classify 仍只在「确定性嗅探无结论且 intent != raw」时触发：链接错误现已由确定性嗅探直接命中 error，不再依赖 classify（旧测 A 态 301.5ms、classifiedShape=error；因原文保真，输出不变）。
  • 错误保真已复核：标准 error: 错误 267B→267B、rustc error[E0308] 145B→145B，L0 与委派 classify 成功两条路径均 100% 保留原文；fact/reason/nextSteps 只进 structuredContent.error，不再替换正文或追加 SLOT_UNAVAILABLE。
  • vision 本地未接（见结论）；decide / embedding 不在 govern 链，本轮未纳入对比。

四、方法与复现

  • 脚本：reports/tg_slot_compare.py（Python 标准库）：Unix socket 手写 HTTP/1.1 调 POST /govern；内置 127.0.0.1:18080 委派 stub 模拟宿主会话模型；以 HOME=/tmp/tg_nohome 起第二 daemon 模拟「无配置」。
  • 数据：reports/tg_slot_compare.json（A/B 每例的 shape、slmStatus、输出字节、延迟、预览，以及三态）；边界修复复测见 reports/tg_boundary_retest-2026-11-14.json（直连 /govern 与适配器处理器两种通道）。
